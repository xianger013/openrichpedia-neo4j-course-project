# 1. 数据集与任务分析

## 1.1 作业要求如何拆解

老师要求“从 OpenKG 选择一个数据集，用 MySQL 或 Neo4j 可视化并写报告”。本项目把它拆成六步：

```text
OpenRichpedia 数据
        ↓
理解实体和关系
        ↓
数据清洗与 ID 统一
        ↓
转换为节点表 / 关系表
        ↓
导入 Neo4j + Cypher 查询
        ↓
可视化截图 + 实验报告
```

真正需要掌握的数据库知识不多：节点、关系、属性、唯一约束，以及 `MATCH / MERGE / RETURN` 等基本 Cypher。

## 1.2 为什么选择 Neo4j

关系型数据库适合二维表，但知识图谱的核心对象天然是图。若使用 Neo4j：

```text
Beijing ──HAS_SIGHT──> Forbidden City
   │
   └──HAS_IMAGE──> Image
```

可以直接映射成：

```cypher
(:City)-[:HAS_SIGHT]->(:Sight)
(:Entity)-[:HAS_IMAGE]->(:Image)
```

因此数据建模和可视化都更直接。

## 1.3 OpenRichpedia 是什么

OpenRichpedia / Richpedia 是面向多模态知识图谱的数据资源。上游不仅包含文本实体，还把实体与视觉资源建立联系。原仓库 README 说明完整关系三元组以 NT/RDF 形式发布，同时仓库本身保留了网站使用的一部分结构化数据。

本作业不尝试复现完整 Richpedia 系统，而选用仓库中可直接复现、规模适合课程作业的子集。

## 1.4 本项目实际使用的数据

| 文件 | 内容 | 转换后的图结构 |
|---|---|---|
| `city.js` | 城市及其景点层级 | `City -[:HAS_SIGHT]-> Sight` |
| `city_sight.js` | Wikidata QID 与地点名称 | `Place` 节点 |
| `pic_city.js` | 地点 QID 与图片 ID | `Place/City -[:HAS_IMAGE]-> Image` |
| `people.js` | 人物 ID 与姓名 | `Person` 节点 |
| `pic_people.js` | 人物与图片 ID | `Person -[:HAS_IMAGE]-> Image` |
| `contain.js` | 图片资源之间的关联 | `Image -[:CONTAINS]-> Image` |

## 1.5 图谱形式化表示

将知识图谱定义为有向属性图：

$$
G=(V,E)
$$

节点集合：

$$
V=V_{city}\cup V_{sight}\cup V_{place}\cup V_{person}\cup V_{image}
$$

关系集合：

$$
E=E_{has\_sight}\cup E_{has\_image}\cup E_{contains}
$$

节点 $v\in V$ 至少具有以下属性：

$$
P(v)=\{id,name,kind,source\_file\}
$$

这样既能在 Neo4j 中直观展示，也保留了每条数据来自哪个上游文件的可追溯信息。
